# MCP-сервер (шаблон)

Два варианта запуска одного и того же набора tool-ов:

| Файл | Транспорт | Когда использовать |
|---|---|---|
| `server_stdio.py` | stdio | Агент на той же машине, запускает сервер как процесс |
| `server_http.py` | HTTP/SSE | Сервер крутится отдельно, подключение по сети |

## Как добавить свой tool

Все инструменты живут в `tools/example_tools.py` в функции `register_tools(mcp)`.
Добавь новую функцию с декоратором `@mcp.tool()`:

```python
@mcp.tool()
async def my_tool(param: str) -> dict:
    """Описание — его читает агент, чтобы понять, когда вызывать tool."""
    return await http_request("GET", f"https://api.example.com/{param}")
```

Правила:
- Пиши понятный docstring — это то, по чему агент решает вызвать инструмент.
- Аннотируй типы параметров и результата — из них строится схема.
- Для внешних вызовов используй `http_request()` — в нём ретраи и обработка ошибок.
- Секреты бери из `os.environ` (заполняются из `.env`), не хардкодь.

## Проверка

```bash
python mcp-server/server_stdio.py
```

Затем подключи сервер к агенту и вызови tool `echo`, чтобы убедиться в связности.

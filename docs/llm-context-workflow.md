# Оптимизация контекста для нейронки: три слоя

Чтобы запросы к модели были точными и дешёвыми по токенам, в репозитории заложены
три независимых, но дополняющих друг друга слоя. Каждый решает свою задачу.

| Слой | Инструмент | Что оптимизирует | Где живёт |
|---|---|---|---|
| Намерение | **OpenSpec** | модель строит по спеке, а не переугадывает задачу | `openspec/` (после init), `docs/setup-openspec.md` |
| Память | **Graphiti** | персистентные факты/решения/требования между сессиями | `graph/` |
| Структура кода | **code-graph** (cgraphy) | агент читает нужный символ, а не файлы целиком | `.cgraphy/` (после индексации) |

## 1. OpenSpec — слой намерения

Spec-driven development: вместо «сделай фичу» ты через слэш-команды агента
(`/opsx:propose` → `/opsx:apply` → `/opsx:archive`) фиксируешь структурированную
спеку изменения. Модель строит по ней, затем спека архивируется в источник правды.
Меньше итераций, меньше «уверенно сделал не то».

Настройка: см. `docs/setup-openspec.md`.

## 2. Graphiti — слой памяти (temporal knowledge graph)

Это НЕ граф структуры кода. Graphiti копит сущности и факты во времени
(разговоры, документы, требования) и отдаёт агенту релевантный подграф вместо
повторного чтения всего подряд. Встроенные типы сущностей —
`Requirement`, `Procedure`, `Person`, `Organization`, `Document` — прямо ложатся
на кейс «Требования из встречи».

Когда полезно на хакатоне:
- накопить требования/решения из транскриптов встреч в единый граф;
- дать агенту память между шагами длинной задачи.

Настройка: см. `graph/README.md`.

## 3. code-graph (cgraphy) — слой структуры кода

Именно этот слой делает «запросы к нейронке оптимальными» в смысле навигации по
коду: tree-sitter парсит проект в граф символов/вызовов/импортов, агент запрашивает
нужный подграф (пара тысяч токенов) вместо чтения файлов целиком — до ~10× меньше
токенов и меньше tool-calls.

Настройка: см. раздел «code-graph» в `graph/README.md`.

## Как это связано с MCP

Graphiti и code-graph подключаются к агенту как MCP-серверы. Регистрация —
в `.cursor/mcp.json` (для Cursor). Для GigaCode те же серверы нужно прописать в его
собственном конфиге MCP (формат уточнить у организаторов).

## Рекомендованный порядок внедрения

1. `openspec init` — сразу, это дёшево и структурирует работу.
2. code-graph — как только есть кодовая база кейса (наибольший выигрыш по токенам).
3. Graphiti — если задача требует памяти/накопления фактов (аналитический кейс).

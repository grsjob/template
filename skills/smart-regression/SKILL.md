# Назначение

На вход — diff PR и карта тест-кейсов. Агент определяет, какие тесты реально
затронуты изменениями, и выдаёт приоритизированный список с обоснованием, чтобы
не гонять полный регресс.

# Входные данные

- источник: diff/patch пул-реквеста + карта/каталог тест-кейсов
- формат: unified diff + список тест-кейсов (из TMS)

# Инструменты (MCP)

- `git_diff` (обёртка над GitLab API) — получить diff PR
- `tms_testcases` (обёртка над TMS API) — получить карту тест-кейсов
- (опц.) `fetch_url` — история дефектов/связей

# Алгоритм

1. Разобрать diff: какие файлы/модули/функции затронуты.
2. Смапить изменения на тест-кейсы (по модулю, тегам, истории связей).
3. Приоритизировать: близость к изменению × критичность области × риск.
4. Сформировать список «запустить обязательно / желательно / можно пропустить».
5. К каждому пункту — краткое обоснование выбора.

# Формат выхода

Приоритизированный список тестов с обоснованием (`templates/test_mapping.md`).

# Правила и ограничения

- Обоснование обязательно для каждого теста в списке «обязательно».
- Явно указывать риск пропуска для тестов из категории «можно пропустить».

# Самопроверка (чек-лист)

- [ ] все затронутые модули покрыты хотя бы одним тестом
- [ ] у каждого выбранного теста есть обоснование
- [ ] оценён риск для пропущенных тестов

# Бенчмарк

Сокращение времени регрессии; % пропущенных дефектов vs. полный прогон.

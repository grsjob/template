# Назначение

На вход — кодовая база или модуль. Агент находит проблемы (через SonarQube /
AppSec-инструменты), сортирует по приоритету и генерирует PR с фиксами для
типовых, безопасных для автоправки случаев.

# Входные данные

- источник: путь к репозиторию/модулю или ссылка на проект
- формат: код + (опц.) baseline из SonarQube

# Инструменты (MCP)

- `sonar_issues` (обёртка над SonarQube API) — получить список проблем
- `git_create_mr` (обёртка над GitLab API) — создать PR/MR с фиксом
- (опц.) `fetch_url` — правила/справочник по нарушениям

# Алгоритм

1. Получить список проблем и метрики (severity, тип, файл, строка).
2. Приоритизировать: критичность × частота × стоимость фикса.
3. Разделить на «автофикс возможен» и «нужен человек».
4. Для автофиксов сгенерировать патч + описание PR (`templates/pr_template.md`).
5. Создать PR через `git_create_mr`, для остальных — задачи с приоритетом.

# Формат выхода

1) Приоритизированный список проблем. 2) Набор PR с фиксами (по `templates/pr_template.md`).

# Правила и ограничения

- Автофиксить только типовые, безопасные случаи (форматирование, неиспользуемое,
  простые null-checks). Логику не менять без явного подтверждения.
- Каждый PR — атомарный и с понятным описанием, что и почему изменено.

# Самопроверка (чек-лист)

- [ ] проблемы отсортированы по обоснованному приоритету
- [ ] автофиксы не меняют бизнес-логику
- [ ] каждый PR проходит сборку/линтер
- [ ] описание PR ссылается на найденную проблему

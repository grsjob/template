# Назначение

Аналитик даёт транскрипт встречи → агент извлекает требования, структурирует их
по шаблону БТ и создаёт задачи в SberTrack. Цель — сократить время ручной
подготовки БТ и повысить полноту по чек-листу требований.

# Входные данные

- источник: транскрипт или текстовая запись встречи с заказчиком
- формат: текст (возможно, с таймкодами и спикерами)

# Инструменты (MCP)

- `create_bt` — создать бизнес-требование в SberTrack
- (опц.) `fetch_url` — подтянуть контекст из вики/справочника

# Алгоритм

1. Прочитать транскрипт, выделить: цель, участников, договорённости, открытые вопросы.
2. Сгруппировать высказывания в атомарные требования (одно требование = одна мысль).
3. Для каждого требования заполнить шаблон БТ (`templates/bt_template.md`).
4. Пометить неоднозначные места как `[УТОЧНИТЬ]`, не выдумывать.
5. Создать БТ в SberTrack через `create_bt`.

# Формат выхода

Список БТ по `templates/bt_template.md` + ссылки на созданные задачи в SberTrack.

# Правила и ограничения

- Не додумывать требования, которых не было на встрече.
- Каждое требование — проверяемое и атомарное.
- Спорные формулировки выносить в раздел «Открытые вопросы».

# Самопроверка (чек-лист)

- [ ] каждое требование атомарно и проверяемо
- [ ] заполнены обязательные поля шаблона БТ
- [ ] открытые вопросы вынесены отдельно
- [ ] задачи реально созданы в SberTrack (есть ссылки)

# Бенчмарк

Время ручной подготовки БТ vs. с агентом; полнота по чек-листу требований.
